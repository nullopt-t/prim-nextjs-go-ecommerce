## 7. Defects found and fixed

### 7.1 `PATCH /admin/orders/{id}/tracking` returned 500 instead of 404
The service mapped `pgx.ErrNoRows` to a typed 404, but the handler re-wrapped **every** error as `apierr.InternalServerError`, masking the mapping. Fixed to propagate the typed error, matching the neighbouring handlers.
- File: `backend/internal/order/order_handler.go`
- Verification: a random order id now returns `404` with the canonical error envelope.

### 7.2 Concurrent checkout deadlocks (`40P01`)
Before the fix, a focused 25s checkout run produced **149** PostgreSQL deadlocks. Three interacting causes were fixed:

1. **Missing cart lock.** Checkout claimed to lock the cart `FOR UPDATE`, but `GetCartByUserID` had no lock. Added `LockCartByUserID` and acquire it before reading items, so same-cart checkouts serialize and cannot create duplicate orders.
2. **Non-deterministic variant lock order.** The reserve loop locked variants in `carted_at` order; concurrent checkouts could take the same locks in opposite order. The loop now sorts by `VariantID`, mirroring `CommitReservationsForOrder`.
3. **Child-first cart mutations.** `AddItem` / `UpdateItemQuantity` / `RemoveItem` / `ClearCart` updated `cart_items` before the parent `carts` row, inverting checkout's parent→child order. All cart mutations now take `LockCartByID` first, establishing one global order: **cart → cart_items / variants**.

- Files: `backend/internal/checkout/checkout_service.go`, `backend/internal/cart/cart_repository.go`
- Verification: `0` deadlocks across all post-fix runs, including **136** concurrent successful checkouts in a focused test and **54–84** per full-suite phase.

## 8. Open finding (not changed)

`GET /products/{product_id}/variants` and `GET /admin/products/{product_id}/variants` are implemented and documented but **never registered**, so they return Gin's raw `404 page not found`. The handlers read `product_id`, while the routers already use `:id`/`:slug` at the same position — Gin rejects differing wildcard names. Fixing this needs a parameter-naming/route decision, so it was left open.
