# Repository Guidelines & Agent Instructions

This repository contains PRIM, a multi-vendor e-commerce platform built with Next.js 16 (App Router) on the frontend and Go (Gin + PostgreSQL + Redis) on the backend.

---

## 1. Git & Contribution Privacy (MANDATORY FOR ALL AGENTS)

Contributions made by AI agents to this repository must remain strictly private, anonymous, and unbranded. All agents operating across this repository MUST adhere to these rules:

1. **NO Co-Authoring Attribution**:
   - NEVER append `Co-Authored-By`, `Co-authored-by`, `Signed-off-by`, or any secondary author metadata to commit messages.
   - Prohibited examples:
     - `Co-Authored-By: Codebuff <noreply@codebuff.com>`
     - `Co-Authored-By: Claude <noreply@anthropic.com>`
     - `Co-Authored-By: Aider <...>`
   - All commits must be attributed exclusively to the repository owner (`Amr Ali`). Never override `user.name` or `user.email`.

2. **NO AI Branding, Watermarks, or Badges**:
   - NEVER insert bot watermarks, badges, or signatures (e.g., `🤖 Generated with Codebuff`, `🤖 Generated by Claude`, `Assisted by Cursor`, etc.) anywhere in:
     - Git commit messages or subject lines
     - Pull request titles, descriptions, or PR templates
     - Source code comments, annotations, or docstrings
     - Markdown documentation or README files

3. **Conventional Commits & Template**:
   - Commit messages must follow clean, conventional format as defined in `.gitmessage`:
     `feat(domain): description`, `fix(domain): description`, `docs(domain): description`, `test(domain): description`, `refactor(domain): description`.
   - Keep commit messages concise, descriptive, and professional. Follow the rules specified in `.gitmessage`.

## 2. Monorepo Organization

- `frontend/`: Next.js 16 App Router, TypeScript, Tailwind CSS, shadcn/ui primitives.
  - See `frontend/AGENTS.md` for frontend-specific rules.
- `backend/`: Go 1.24, Gin HTTP framework, PostgreSQL (pgx), Redis session store, Kafka event streaming.
  - See `backend/AGENTS.md` for backend-specific architecture rules.
- `docker-compose.yml`: Local full-stack development environment.

---

## 3. Engineering Discipline

1. **Clean Architecture**: Source code dependencies point inward. Domain models and business logic never depend on external frameworks, HTTP routers, or SQL drivers.
2. **Explicit Dependency Injection**: Use constructors only (`NewService`, `NewHandler`, `NewRouter`). No package-level globals, singletons, or hidden state.
3. **Bilingual Integrity**: Every user-facing UI string must have corresponding entries in both `frontend/messages/en.json` and `frontend/messages/ar.json`.
4. **Verified Changes**: Always verify changes before completion (`go test ./...` in backend, `npx tsc --noEmit` in frontend).
